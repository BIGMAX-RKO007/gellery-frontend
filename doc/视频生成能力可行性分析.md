# 视频生成能力可行性分析

> 记录日期：2026-09-27  
> 目标项目：Google AI Edge Gallery Android

## 1. 结论

存在文字生成视频、图片生成视频的开源模型，但以当前手机硬件、Android 推理生态和本项目架构来看，**不建议把完整视频生成模型直接放到手机本地运行**。

可行方案按推荐顺序为：

1. **手机 App + 云端视频生成 API**：最现实，效果最好，也最容易接入。
2. **手机本地智能剪辑/合成**：模型生成脚本、分镜、字幕和配音，再使用 Android Media3 把图片、视频和音频合成为 MP4；可以做到大部分离线运行。
3. **纯手机端生成视频**：目前只适合研究验证，速度、内存、功耗和兼容性风险很高，不适合直接作为正式功能。

## 2. 当前项目为什么不能直接加入视频生成模型

项目现有的 `LlmModelHelper` 是大语言模型接口：

- 输入：文字、`Bitmap` 图片、音频字节。
- 输出：流式文字。
- 没有视频帧张量、latent、VAE 解码、视频编码或 MP4 输出接口。

项目模型清单中的任务只有聊天、Prompt Lab、Agent、图片问答、音频问答、Tiny Garden、Mobile Actions 和图片分割，没有 text-to-video、image-to-video 或 video-to-video 类型。

因此，视频生成不是“在模型列表里增加一条 JSON”就能实现。它需要独立的运行时、模型生命周期、长任务调度、进度展示、视频编码、文件管理、预览和分享页面。

## 3. 可考虑的开源视频生成模型

### Wan 2.1 T2V 1.3B

- 支持文字生成视频。
- 官方称 1.3B 版本约需 8.19 GB 显存。
- 官方示例中，RTX 4090 生成 5 秒 480P 视频约需 4 分钟（未使用额外优化）。
- 这是“消费级桌面 GPU 可运行”，不是“普通手机可运行”。

官方项目：<https://github.com/Wan-Video/Wan2.1>

### LTX-Video 2B Distilled

- 支持文字/图片生成视频，蒸馏版减少了采样步数。
- 相比 13B 版本更轻，但官方主要实现仍基于 PyTorch、CUDA 和桌面 GPU。
- 官方给出的 Q8 示例面向 RTX 4060 8 GB 显存，并非 Android GPU/NPU。

官方项目：<https://github.com/Lightricks/LTX-Video>

### 为什么不能只看“1.3B/2B”

视频生成除了主 Transformer，还通常需要文本编码器、Video VAE、调度器和多帧 latent。分辨率和帧数会快速放大中间张量内存。手机的 12 GB 系统内存不能等同于桌面显卡的 8 GB 专用显存，而且 Android 端不能直接运行依赖 CUDA 的官方代码。

要纯本地运行，还需要解决：

- 模型格式转换和不支持算子。
- LiteRT/GPU/NPU 后端兼容性。
- 量化后的画质损失。
- 峰值内存和系统杀进程。
- 数分钟甚至更久的生成时间。
- 发热、降频和电量消耗。
- VAE 解码后的帧序列编码为 MP4。

## 4. 推荐方案一：云端生成，手机负责交互

推荐调用具备视频生成能力的服务，例如 Gemini API 中的视频生成模型，或者在自有 GPU 服务器部署 Wan/LTX。

建议调用链：

```text
Android App
  -> 业务后端（鉴权、额度、任务记录）
  -> 视频生成服务
  -> 异步任务 ID
  -> App 查询进度
  -> 下载 MP4
  -> 本地预览、保存或分享
```

不要把云服务 API Key 直接写进 APK；反编译后很容易泄露。正式产品应由业务后端保存密钥、限制额度并审核请求。

该路线需要在项目中新建独立的 `VideoGenerationRepository` 和页面，而不是改造 `LlmModelHelper`。长任务应支持取消、失败重试、断点恢复和后台通知。

Google 官方视频生成说明：<https://ai.google.dev/gemini-api/docs/video>

## 5. 推荐方案二：手机本地“智能视频制作”

如果“视频制作”是把图片、已有视频、字幕、配音和音乐组合成短视频，而不是凭空生成连续画面，那么手机本地完全可行：

1. Gemma 根据主题生成文案、分镜和字幕。
2. 用户选择本地图片/视频，或从服务端生成分镜图片。
3. Android TTS 或音频模型生成旁白。
4. Media3 Transformer 负责裁剪、缩放、滤镜、叠字、拼接、混音和导出 MP4。

这种方案速度快、稳定、成本低，也更符合手机端硬件条件。Media3 支持多素材编排、图片转视频片段、音视频混合、效果和 MP4 导出。

Android 官方文档：

- <https://developer.android.com/media/media3/transformer/transformations>
- <https://developer.android.com/media/media3/transformer/composition>

## 6. 如果需求是“理解视频”而不是“生成视频”

当前 Gemma 4 在这个项目中支持图片和音频输入，但项目没有直接的视频输入接口。可以实现一个预处理流程：

1. 从视频按时间间隔抽取关键帧。
2. 提取或转写音轨。
3. 将少量关键帧作为图片、将音频/转写文本作为上下文交给 Gemma。
4. 输出摘要、字幕、章节、标签或问答结果。

这比本地生成视频容易得多，但必须限制帧数，否则会超出模型上下文和内存限制。

## 7. 对本项目的建议

如果准备做第一版视频功能，建议按以下顺序：

1. 先实现“AI 文案/分镜 + 本地素材合成短视频”。
2. 使用 Media3 完成预览、剪辑、字幕、配音和 MP4 导出。
3. 再接入云端文字/图片生成视频服务，作为可选素材来源。
4. 最后才考虑纯手机端视频扩散模型，并将其作为特定高端机型的实验功能。

不建议当前直接下载 Wan/LTX 权重并加入模型清单，因为现有 LiteRT-LM 运行时无法执行这些视频扩散模型。
