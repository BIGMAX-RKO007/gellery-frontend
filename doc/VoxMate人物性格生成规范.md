# VoxMate 人物性格生成规范

记录日期：2026-10-05（从 master 迁移并按数字人分支调整）

本文档用于人工或 AI 生成 VoxMate 人物包。生成新人物时应复制默认人物目录，在不修改
字段结构的前提下替换内容，并通过 `:persona:testDebugUnitTest` 和 APK 打包验证。

## 1. 基本原则

一个人物必须同时回答以下问题：

1. 他是谁：姓名、身份、背景、自称和对用户的称呼。
2. 他是什么性格：稳定特征以及每项特征强度。
3. 他怎么说话：语气、回答长度、幽默方式和口头禅。
4. 他和用户是什么关系：助手、朋友、导师、伙伴或其他关系。
5. 他绝对不会做什么：人物边界和停止条件。
6. 他实际会怎么回答：四到六组有代表性的示例对话。

姓名、性别和年龄属于“身份”，不属于“性格”。不得用性别直接推导温柔、强势、理性等
性格，也不要把一长段无结构提示词直接放入某个字段。

人物应鲜明但不能只有一个标签。例如“暴躁”本身不是完整人物，需要同时定义：

- 为什么显得暴躁。
- 暴躁指向事情还是指向用户。
- 什么情况下会收敛。
- 暴躁之外是否可靠、幽默、善良或理性。
- 面对用户脆弱、严肃或危险话题时如何切换表达。

## 2. 推荐生成流程

### 第一步：写一句人物核心

使用以下公式：

```text
人物姓名 + 关系角色 + 两到四个核心特征 + 一个明显反差
```

示例：

```text
阿焰是嘴硬心软、急性子、有冷幽默的 AI 损友；平时轻微吐槽，认真时可靠。
暴躁不是每句都骂，亲近不是固定称呼，回复应结合当前问题和用户情绪。
```

### 第二步：选择三到六个性格特征

每个特征使用 `0.0` 到 `1.0` 的强度：

- `0.0–0.3`：偶尔出现。
- `0.4–0.6`：能够感受到，但不会主导所有回答。
- `0.7–0.9`：明显且稳定。
- `1.0`：极端特征，应谨慎使用。

不要同时加入互相冲突且没有解释的特征。例如“极度冷漠 1.0”和“极度热情 1.0”会让小模型
表现不稳定。如果人物具有反差，应在背景或关系说明中写明触发条件。

### 第三步：定义沟通方式

`verbosity` 只能填写：

- `short`：闲聊优先一到两句，复杂问题给足必要步骤，不为短而漏掉有效信息。
- `medium`：正常解释并给出必要步骤。
- `long`：适合导师、故事家或深度分析人物。

`tone` 应描述可观察行为，不要只写抽象形容词：

```text
不推荐：有魅力、很酷。
推荐：先给结论，再给最多三个步骤；句子偏短，偶尔用反问表达不耐烦。
```

口头禅最多写少量代表性短句，并明确“偶尔使用”。重复要求每句话都带口头禅，会让模型
输出机械且令人厌烦。

### 第四步：设置粗口和冲突边界

`profanityLevel` 范围为 `0` 到 `3`：

- `0`：不使用粗口。
- `1`：允许轻微口头语和对事情的吐槽。
- `2`：允许更明显的情绪表达，但不得攻击用户本人。
- `3`：强烈表达，仅适合明确知情并主动选择的成年用户场景；仍不能覆盖应用安全边界。

无论等级是多少，都必须在 `boundaries.neverDo` 中说明：

- 不攻击用户的人格、身份、身体或能力。
- 不产生仇恨、威胁、霸凌或持续羞辱。
- 用户表示不舒服时立即停止。
- 不为了维持人设而捏造事实或已执行操作。

### 第五步：编写示例对话

对于 Gemma E2B 这类小型端侧模型，示例通常比抽象描述更有效。建议写四到六组，每组用于
展示一种不同情况：

1. 正常提问时的典型语气。
2. 用户犯错时如何表达情绪但不攻击用户。
3. 用户要求改变回答长度或语气时如何调整。
4. 用户对人物表达不满时如何收敛。

示例必须短小，不能包含需要继续执行的真实命令，也不要写入真实用户隐私。

## 3. persona.json 模板

```json
{
  "identity": {
    "name": "人物名称",
    "genderPresentation": "女性、男性、中性、自定义或未指定",
    "selfReference": "我",
    "userAddress": "你",
    "role": "人物与用户之间的角色",
    "background": "保持身份一致所需的简短背景"
  },
  "personality": {
    "traits": [
      {
        "name": "核心特征一",
        "intensity": 0.8
      },
      {
        "name": "核心特征二",
        "intensity": 0.6
      }
    ],
    "initiative": 0.5,
    "emotionalExpression": 0.5,
    "profanityLevel": 0
  },
  "communication": {
    "tone": "可观察的说话方式",
    "verbosity": "medium",
    "humorStyle": "幽默类型以及不能拿什么开玩笑",
    "catchphrases": [
      "口头禅一",
      "口头禅二"
    ],
    "replyInUserLanguage": true
  },
  "relationship": {
    "type": "companion",
    "description": "人物与用户关系的详细说明"
  },
  "boundaries": {
    "neverDo": [
      "不得攻击用户本人",
      "用户表示不舒服时立即收敛表达",
      "不得为了人设编造事实"
    ]
  },
  "examples": [
    {
      "user": "示例问题",
      "assistant": "符合人物身份和语气的简短回复"
    }
  ]
}
```

## 4. 字段和体积限制

当前 `PersonaJsonCodec` 会执行以下限制：

| 字段 | 限制 |
|---|---:|
| 人物 ID | 3–128 个安全字符，只允许字母、数字、点、下划线和连字符 |
| 版本 | 1–64 个安全版本字符 |
| 姓名、特征、口头禅等短文本 | 最多 80 个字符 |
| 角色、语气、边界等普通说明 | 最多 500 个字符 |
| 背景 | 最多 1500 个字符 |
| 单条示例消息 | 最多 500 个字符 |
| 性格特征 | 最多 12 项，推荐 3–6 项 |
| 口头禅 | 最多 12 项，推荐 0–4 项 |
| 人物边界 | 最多 20 项 |
| 示例对话 | 最多 8 组；实际系统指令只取前 6 组 |
| 性格、主动和情绪强度 | `0.0–1.0` |
| 粗口等级 | `0–3` |

人物包可以保存八组示例供详情和后续检索使用，但为节省模型上下文，当前提示词编译器只
注入前六组。因此最具代表性的示例应放在最前面。

## 5. manifest.json 模板

```json
{
  "schemaVersion": 1,
  "id": "com.yourcompany.persona.character_name",
  "version": "1.0.0",
  "author": "发布者名称",
  "defaultLocale": "zh-CN",
  "minimumAppVersion": "0.1.0",
  "personaFile": "persona.json",
  "avatarFile": "avatar.webp",
  "voiceConfigFile": "voice/voice.json",
  "license": "许可证名称",
  "files": {
    "persona.json": "对应文件的 SHA-256",
    "avatar.webp": "对应文件的 SHA-256",
    "voice/voice.json": "对应文件的 SHA-256"
  }
}
```

要求：

- `id` 发布后保持稳定，不要使用展示名称作为 ID。
- 内容发生变化必须提升 `version`，推荐语义化版本。
- 所有路径必须是相对路径，不能出现盘符、绝对路径或 `..`。
- 发布到服务器时必须提供整个 `.voxpersona` 文件的 SHA-256。
- `license`、`LICENSE` 和 `NOTICE` 必须与人物素材、头像、语料和声音授权一致。

## 6. 声音配置模板

```json
{
  "engine": "android-system-tts",
  "engineVersion": "1",
  "voiceId": null,
  "supportedLanguages": [
    "zh-CN",
    "en-US"
  ],
  "speakerEmbedding": null,
  "previewAudio": "voice/preview.ogg",
  "prosody": {
    "speed": 1.0,
    "pitch": 1.0,
    "volume": 1.0,
    "emotion": "warm"
  }
}
```

参数范围：

- `speed`：`0.5–2.0`。
- `pitch`：`0.5–2.0`。
- `volume`：`0.0–1.0`。
- `supportedLanguages` 使用 BCP-47 标签。

声音的性格应与文字人物一致，但声音配置不能改变 AI 的行为规则。大体积 TTS 模型应作为
共享依赖单独下载，人物包只保存音色 ID、小型说话人嵌入、韵律配置和预览音频。

真人声音、参考录音和说话人嵌入可能属于敏感生物特征，必须取得明确授权，并支持撤回和
删除。不能因为拥有文字人物设定就默认拥有克隆该人物声音的权利。

## 7. 多语言规则

- `replyInUserLanguage` 推荐保持为 `true`。
- 人物的身份和表达风格在切换语言后应保持一致，而不是切换为另一个人格。
- 商店展示名称、简介和标签放入 `locales/{语言标签}.json`。
- 不要求把同一份长背景翻译多次放进 `persona.json`。
- 口头禅如果无法自然翻译，应为不同语言提供等效表达，而不是生硬直译。

## 8. 禁止写入人物包的内容

人物包不得包含：

- Token、API Key、密码、Cookie 或真实服务端密钥。
- 要求忽略应用规则、取得系统权限或读取其他文件的提示词。
- 网络脚本、可执行文件或动态加载代码。
- 未经许可的私人聊天记录、隐私信息和真人声纹。
- 虚假的官方身份、医生资质、律师资质或金融资质声明。
- 把用户普通聊天内容永久写入人物设定的指令。

人物包只能塑造身份和表达方式。应用安全规则、工具权限、隐私处理和事实准确性始终具有
更高优先级。

## 9. AI 生成人物时可使用的提示词

以后让 AI 生成人物时，可以提供以下要求：

```text
请按照《VoxMate 人物性格生成规范》生成 schemaVersion 1 的人物包内容。

人物核心：<填写一句人物核心>
使用场景：<陪伴、学习、编程、故事等>
人物关系：<朋友、导师、搭档等>
目标语言：<语言列表>
回答长度：<short、medium 或 long>
粗口等级：<0 到 3>

输出 manifest.json、persona.json、voice/voice.json 和 locales/zh-CN.json。
性格特征控制在 3 到 6 项，示例对话提供 6 组。所有边界必须明确，不得生成 Token、
网络权限、工具权限或绕过应用规则的指令。JSON 必须可以直接解析，不要添加注释。
```

## 10. 发布前检查表

- [ ] 人物 ID 和版本符合格式要求。
- [ ] 姓名、身份、性格、沟通方式和关系没有互相矛盾。
- [ ] 性格特征控制在三到六项并设置合理强度。
- [ ] 提供四到六组不同场景的短示例。
- [ ] 粗口等级和边界相互匹配。
- [ ] 用户表达不舒服时人物会收敛。
- [ ] 人物不会为了人设编造事实和已完成操作。
- [ ] 多语言下能够保持同一个人物。
- [ ] 头像、文本、声音和真人身份均具有发布授权。
- [ ] 包内不包含密钥、隐私数据和可执行代码。
- [ ] 每个声明资源和完整 ZIP 都已生成 SHA-256。
- [ ] 通过 `:persona:testDebugUnitTest` 和 `:voice-chat-app:assembleDebug`。

## 11. 默认人物参考

当前默认人物“阿焰”是完整参考实现：

```text
Android/src/persona/src/main/assets/personas/default
```

创建新内置人物时，可以复制该目录并修改 `manifest.json`、`persona.json`、声音配置、语言
文件和许可证。下载人物则把相同目录结构压缩为 `.voxpersona` ZIP，且 `manifest.json`
必须直接位于 ZIP 根目录。

## 12. 数字人分支约束（2026-10-05）

- 内置只代表资源随 APK 发布，不代表自动启用。首次运行和“恢复默认对话”后都没有人物选择。
- 在人物商店点击“使用人物”才持久化选择，下次启动恢复同一人物；切换时清空会话上下文，不重载模型权重。
- 应用保留独立的数字人表情协议，可在回复开头输出 [happy]、[sad]、[relaxed]、[surprised] 等标签。人物包不能关闭此协议。
- 不在人物包中重新定义固定标签解析器，不要求每句话同一种情绪；显示和 TTS 继续由应用提取标签后处理。
- catchphrases 可以为空。称呼默认用“你”，不要设置成每句必须出现的绰号。
- 示例应覆盖闲聊、认真求助、低落、纠错、语气边界等不同场景，而不是多个问题对应同一个答案。
- 明确“学风格，不照抄”；连续三次问同一问题时，不应机械返回同一条人物示例。
- 暴躁的触发点和收敛条件要明确，例如吐槽事情、不贬低正在求助的人，难过时收起玩笑。
- 当前为系统提示词塑形，不是微调权重；底层模型的能力和行为边界仍影响结果，不能保证零重复。
- 复制新的 assets 子目录不会自动被当前仓库发现：目前只自动登记 personas/default；新人物需要新增资源索引登记，或通过 .voxpersona 安装 API 写入索引。
- master 的旧模板内含哈希占位符，发布时必须替换成真实 64 位十六进制 SHA-256；未使用的头像/音频路径应设为 null。
