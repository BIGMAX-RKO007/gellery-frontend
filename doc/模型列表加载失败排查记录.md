# 模型列表加载失败排查记录

> 记录日期：2026-09-27  
> 现象：应用启动后弹出 `Failed to load model list`，并提示检查网络连接。

## 1. 定位结论

本次问题的首要原因不是 Android 网络权限，而是**应用版本号和远端模型列表文件不匹配**。

当前配置为：

```kotlin
// Android/src/app/build.gradle.kts
versionName = "1.0.20"
```

应用会把版本号中的点替换为下划线，并请求：

```text
https://raw.githubusercontent.com/google-ai-edge/gallery/refs/heads/main/model_allowlists/1_0_20.json
```

但是当前本地及 GitHub 仓库的 `model_allowlists/` 目录中最高只有 `1_0_19.json`，不存在 `1_0_20.json`。因此请求返回非 200 结果，首次安装时又没有磁盘缓存，最终弹出截图中的错误。

即便修复版本错配，在中国大陆网络环境下，`raw.githubusercontent.com` 仍可能无法稳定访问，这是需要单独处理的第二层问题。

## 2. 触发链路

1. `MainActivity.kt` 启动时调用 `modelManagerViewModel.loadModelAllowlist()`。
2. `ModelManagerViewModel.loadModelAllowlist()` 读取 `BuildConfig.VERSION_NAME`。
3. `1.0.20` 被转换为 `1_0_20`。
4. `getAllowlistUrl()` 拼接 GitHub Raw 地址。
5. `getJsonResponse()` 使用 `HttpURLConnection` 发起 GET 请求。
6. 只有 HTTP 200 才会解析 JSON；其他状态统一返回 `null`。
7. 本地不存在旧缓存时，设置 `loadingModelAllowlistError = "Failed to load model list"`。

关键源码位置：

- `Android/src/app/build.gradle.kts`：版本号。
- `Android/src/app/src/main/java/com/google/ai/edge/gallery/ui/modelmanager/ModelManagerViewModel.kt`：模型列表 URL 和加载/回退逻辑。
- `Android/src/app/src/main/java/com/google/ai/edge/gallery/common/Utils.kt`：HTTP 请求实现。
- `Android/src/app/src/main/java/com/google/ai/edge/gallery/ui/home/HomeScreen.kt`：错误弹窗。

## 3. 如何验证

### 3.1 浏览器验证

分别在手机浏览器中打开：

```text
https://raw.githubusercontent.com/google-ai-edge/gallery/refs/heads/main/model_allowlists/1_0_19.json
https://raw.githubusercontent.com/google-ai-edge/gallery/refs/heads/main/model_allowlists/1_0_20.json
```

预期：`1_0_19.json` 能返回 JSON；`1_0_20.json` 不存在。如果前一个地址也无法打开，则同时存在 GitHub Raw 网络可达性问题。

### 3.2 日志验证

连接设备后可筛选以下日志标签：

```text
AGModelManagerViewModel
AGUtils
```

通常会看到请求的完整 URL，以及 `HTTP error: 404`、DNS、连接超时或证书异常等具体原因。

## 4. 修复方案

### 方案 A：开发阶段的最小改动

把 `versionName` 临时改回已有配置文件的 `1.0.19`。

优点：改动最小，能快速验证后续页面。  
缺点：版本号被模型清单约束，不适合作为长期设计。

### 方案 B：为 1.0.20 补齐模型列表

以确认兼容的 `1_0_19.json` 为基础，新增 `model_allowlists/1_0_20.json` 并将它部署到应用实际访问的服务。

优点：保持应用版本号不变。  
缺点：如果只在本地新增，而 URL 仍指向 Google 的 GitHub 仓库，安装到手机后依然访问不到本地文件；必须同时修改服务地址或把文件发布到可访问的仓库。

### 方案 C：长期推荐方案

不要让应用版本号与远端清单文件形成一一强绑定：

1. 将一个可用的默认模型列表打包进 `assets` 或 `res/raw`，保证首次离线启动可用。
2. 启动时先加载内置列表，再后台请求远端更新。
3. 远端失败时保留内置列表或最后一次成功缓存，不阻断首页。
4. 服务端使用固定入口（例如 `latest.json`）或返回版本映射，而不是直接使用 `BuildConfig.VERSION_NAME` 拼文件名。
5. 为请求设置连接和读取超时，并向界面传递真实错误类型，区分 404、DNS、超时、证书和 JSON 解析错误。
6. 二次开发部署时，把模型清单放到目标用户可稳定访问的自有 HTTPS/CDN 地址，避免依赖 GitHub Raw。

## 5. 网络权限检查

当前 `AndroidManifest.xml` 已声明：

```xml
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />
```

请求使用 HTTPS，因此该故障不是因为缺少 INTERNET 权限，也不是 Android 明文 HTTP 限制导致的。

## 6. 当前建议

先用方案 A 将版本临时改为 `1.0.19`，确认应用可以加载模型列表；随后按方案 C 增加内置兜底清单并替换成稳定可控的远端地址。这样才能同时解决版本文件缺失、首次启动无缓存和 GitHub Raw 网络不稳定三个问题。

## 7. 当前工作区复核（2026-09-27）

当前工作区的 `Android/src/app/build.gradle.kts` 已配置为：

```kotlin
versionName = "1.0.19"
```

模型清单基础地址定义在 `ModelManagerViewModel.kt`：

```kotlin
private const val ALLOWLIST_BASE_URL =
  "https://raw.githubusercontent.com/google-ai-edge/gallery/refs/heads/main/model_allowlists"
```

完整地址由下面的方法生成：

```kotlin
private fun getAllowlistUrl(version: String): String {
  return "$ALLOWLIST_BASE_URL/${version}.json"
}
```

由于加载时会执行 `BuildConfig.VERSION_NAME.replace(".", "_")`，当前实际请求地址是：

```text
https://raw.githubusercontent.com/google-ai-edge/gallery/refs/heads/main/model_allowlists/1_0_19.json
```

仓库内也有一份对应内容：`model_allowlists/1_0_19.json`。需要更换服务器时，可以修改 `ALLOWLIST_BASE_URL`；需要固定到某个文件时，也可以调整 `getAllowlistUrl()`，但长期仍建议保留内置清单作为离线兜底。
