# 免费文字转语音方案分析

分析日期：2026-09-27

## 结论

当前 Android 版 Gallery 的第一版语音回答，推荐直接使用 Android 系统自带的 `TextToSpeech`：

- API 免费，不需要调用收费的云端语音接口。
- 不需要把额外语音模型打进 APK，接入成本最低。
- 可以接在 Gemma 文本生成完成的位置，实现“用户说话 -> 转成文字 -> Gemma 回答 -> 播放语音”。
- 是否完全离线、中文音色是否可用，取决于手机安装的 TTS 引擎及离线语音包。

如果以后要求所有手机的音色和离线能力保持一致，建议把语音输出封装成接口，再增加 `sherpa-onnx` 实现。

## 方案对比

| 方案 | 费用/许可 | 离线 | Android 接入 | 主要特点 | 建议 |
| --- | --- | --- | --- | --- | --- |
| Android `TextToSpeech` | 系统 API 免费 | 取决于系统语音引擎和语音包 | 最简单 | APK 不增加大型模型，设备间音色可能不同 | 第一版首选 |
| sherpa-onnx | 框架 Apache-2.0；语音模型许可需单独确认 | 是 | 提供 Android、Kotlin/Java 支持 | 可内置中文模型，行为一致，但增加安装包和内存占用 | 稳定离线版首选 |
| Piper | 当前上游代码为 GPL-3.0；每个音色许可也可能不同 | 是 | 需要原生库和模型集成 | 速度快、可离线、有中文音色 | 商业闭源项目需谨慎评估许可 |

“框架免费”不代表所有语音模型都能随意商用。随 App 分发模型时，必须同时核对框架许可证、模型许可证和训练数据限制。

## 推荐的语音对话流程

```text
Idle
  -> Listening       用户开始说话
  -> Recognizing     SpeechRecognizer 得到文字
  -> Thinking        把文字传给 Gemma
  -> Speaking        TextToSpeech 播放 Gemma 最终回答
  -> Listening       播放结束后继续监听
```

第一版建议使用轮流对话：

1. 用户说完后停止录音。
2. 将识别到的文字添加为用户消息。
3. 调用现有 `generateResponse(...)`。
4. 在 `onDone` 中读取最终 AI 文本并播放。
5. TTS 播放结束后再重新开启麦克风。

播放 AI 语音期间应暂停语音识别，否则扬声器播放的回答可能被麦克风再次识别，形成回声循环。

## 建议增加的抽象接口

```kotlin
interface SpeechOutput {
  fun speak(text: String, flush: Boolean = true)
  fun stop()
  fun shutdown()
}
```

第一版由 Android `TextToSpeech` 实现；以后可以增加 sherpa-onnx 实现，而不需要修改聊天业务流程。

## Android TextToSpeech 示例

```kotlin
class AndroidTtsController(
  context: Context,
  private val onReady: (Boolean) -> Unit = {},
) : TextToSpeech.OnInitListener, SpeechOutput {
  private val tts = TextToSpeech(context.applicationContext, this)
  private var ready = false

  override fun onInit(status: Int) {
    ready = status == TextToSpeech.SUCCESS &&
      tts.setLanguage(Locale.SIMPLIFIED_CHINESE) >= TextToSpeech.LANG_AVAILABLE
    onReady(ready)
  }

  override fun speak(text: String, flush: Boolean) {
    if (!ready || text.isBlank()) return
    val queueMode = if (flush) TextToSpeech.QUEUE_FLUSH else TextToSpeech.QUEUE_ADD
    tts.speak(text, queueMode, null, "gemma-reply-${System.nanoTime()}")
  }

  override fun stop() {
    tts.stop()
  }

  override fun shutdown() {
    tts.shutdown()
  }
}
```

实际实现还应设置 `UtteranceProgressListener`：

- `onStart`：将会话状态设为 `Speaking`。
- `onDone`：将状态改回 `Listening`，按需重新开启语音识别。
- `onError`：显示语音播放失败，但保留文字答案。

页面或 ViewModel 销毁时调用 `shutdown()`；用户打断、开始新问题或点击停止时调用 `stop()`。

## “实时说出回答”的两个阶段

### 阶段一：完整回答生成后播放

在 `onDone` 中一次性播放完整答案。实现简单、语音自然，适合先验证产品流程。

### 阶段二：按句流式播放

如果希望 AI 一边生成一边说，不能每收到一个 token 就调用一次 TTS。应该缓存流式 token，遇到 `。！？.!?` 或达到适当长度后，将完整句子用 `QUEUE_ADD` 加入播放队列。

还需要处理：

- 生成速度与播放速度不一致时的队列积压。
- 用户打断时同时停止 Gemma 推理和 TTS。
- 尚未形成完整句子的剩余文本。
- Markdown、代码块、网址和表情的朗读清洗。

## 本地离线方案建议

如果选择 sherpa-onnx，可以优先测试官方列出的中文 VITS 模型。具体模型大小、声音效果和商用许可必须以对应模型说明页为准。

本地模型的典型代价包括原生运行库、数十到数百 MB 的模型资源、首次加载时间和额外内存消耗。因此建议先完成 `SpeechOutput` 抽象和系统 TTS 版本，再根据真机效果决定是否内置本地模型。
