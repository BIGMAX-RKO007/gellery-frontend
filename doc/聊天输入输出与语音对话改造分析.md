# 聊天输入输出与语音对话改造分析

> 记录日期：2026-09-27  
> 目标：定位文字输入/输出接口，并设计基于现有 Gemma 4 的语音对话功能

## 1. 核心结论

当前聊天的高层发送入口是：

```kotlin
LlmChatViewModelBase.generateResponse(
  model = model,
  input = text,
  onError = { error -> /* ... */ },
)
```

底层真正把内容送入 LiteRT-LM 的方法是：

```kotlin
conversation.sendMessageAsync(contents, messageCallback, extraContext)
```

模型返回的是**流式文字片段**，不是等待结束后一次性返回完整字符串。最底层由：

```kotlin
MessageCallback.onMessage(message)
```

接收每个增量片段；业务层将它转换为：

```kotlin
AgentEvent.StreamToken(token, thinking, done)
```

页面最终观察 `ChatViewModel.uiState` 中的消息列表并实时刷新。

如果基于现有页面改造，优先调用 `viewModel.generateResponse()`，不要让 UI 直接依赖 `conversation.sendMessageAsync()`，否则会绕过会话、错误处理、停止生成和消息状态管理。

## 2. 当前文字输入调用链

```text
MessageInputText 文本框
  -> 点击发送按钮
  -> createMessagesToSend(..., text)
  -> ChatPanel.onSendMessage(model, messages)
  -> ChatViewWrapper
       1. viewModel.addMessage(...) 保存用户消息
       2. 提取 text / images / audio
       3. viewModel.generateResponse(model, input, ...)
  -> AgentRequest(query = input, attachments = ...)
  -> AgentRuntimeExecutor.executeStream(...)
  -> LlmSessionManager.generateResponse(...)
  -> model.runtimeHelper.runInference(...)
  -> LlmChatModelHelper.runInference(...)
  -> conversation.sendMessageAsync(...)
```

### 2.1 文本框入口

文件：

```text
Android/src/app/src/main/java/com/google/ai/edge/gallery/ui/common/chat/MessageInputText.kt
```

点击发送时调用 `onSendMessage(createMessagesToSend(...))`。这里主要处理 UI 输入、图片和录音附件，不直接调用模型。

### 2.2 页面桥接层

文件：

```text
Android/src/app/src/main/java/com/google/ai/edge/gallery/ui/llmchat/LlmChatScreen.kt
```

`ChatViewWrapper()` 中的 `onSendMessage` 做三件事：

1. 调用 `viewModel.addMessage()` 将用户消息放入 UI state。
2. 从 `ChatMessage` 中拆出文字、Bitmap 和音频。
3. 调用 `viewModel.generateResponse()`。

### 2.3 推荐的业务发送接口

文件：

```text
Android/src/app/src/main/java/com/google/ai/edge/gallery/ui/llmchat/LlmChatViewModel.kt
```

方法：

```kotlin
generateResponse(
  model: Model,
  input: String,
  images: List<Bitmap> = emptyList(),
  audioMessages: List<ChatMessageAudioClip> = emptyList(),
  onFirstToken: (Model) -> Unit = {},
  onDone: () -> Unit = {},
  onError: (String) -> Unit,
  allowThinking: Boolean = false,
)
```

`generateResponse()` 本身不会加入用户文字气泡，所以从自定义页面调用时，应先调用：

```kotlin
viewModel.addMessage(
  model,
  ChatMessageText(content = text, side = ChatSide.USER),
)
```

再调用 `generateResponse()`。

## 3. 当前文字输出调用链

```text
LiteRT-LM MessageCallback.onMessage(message)
  -> resultListener(partialText, done = false, thinking)
  -> AgentEvent.StreamToken
  -> LlmChatViewModel.generateResponse() collect
  -> updateLastTextMessageContentIncrementally()
  -> uiState.messagesByModel[model.name]
  -> Compose 自动刷新聊天气泡
```

### 3.1 最底层流式回调

文件：

```text
Android/src/app/src/main/java/com/google/ai/edge/gallery/ui/llmchat/LlmChatModelHelper.kt
```

- `onMessage()`：每次获得一段新文字，调用 `resultListener(text, false, thinking)`。
- `onDone()`：调用 `resultListener("", true, null)`。
- `onError()`：调用业务层 `onError(...)`。

`partialResult` 是新增片段，需要按顺序累加，不是每次都返回完整答案。

### 3.2 Agent 流接口

文件：

```text
Android/src/app/src/main/java/com/google/ai/edge/gallery/agent/DefaultAgentRuntimeExecutor.kt
```

`executeStream()` 返回 `Flow<AgentEvent>`：

- `LoopInitiated`：本轮开始。
- `StreamToken`：新增的文字或 thinking 片段。
- `LoopTerminated.finalResponse`：本轮完整最终文本。
- `LoopCancelled`：取消。
- `Error`：错误。

如果要开发独立于现有聊天 UI 的新功能，`executeStream()` 是比直接调用 LiteRT-LM 更合适的底层业务接口。

### 3.3 UI 状态接口

文件：

```text
Android/src/app/src/main/java/com/google/ai/edge/gallery/ui/common/chat/ChatViewModel.kt
```

可通过下面的 StateFlow 获取消息：

```kotlin
viewModel.uiState
```

当前模型的消息位于：

```kotlin
uiState.messagesByModel[model.name]
```

最后一条 AI 文字通常是：

```kotlin
val reply =
  (viewModel.getLastMessage(model) as? ChatMessageText)
    ?.takeIf { it.side == ChatSide.AGENT }
    ?.content
```

## 4. 从其他输入源发送文字

语音识别、蓝牙、串口、WebSocket 或其他模块得到文字后，都可以复用相同入口：

```kotlin
fun submitText(text: String, model: Model) {
  val normalized = text.trim()
  if (normalized.isEmpty()) return

  viewModel.addMessage(
    model = model,
    message = ChatMessageText(content = normalized, side = ChatSide.USER),
  )

  viewModel.generateResponse(
    model = model,
    input = normalized,
    onFirstToken = {
      // 第一段输出到达
    },
    onDone = {
      val finalText =
        (viewModel.getLastMessage(model) as? ChatMessageText)
          ?.takeIf { it.side == ChatSide.AGENT }
          ?.content
          .orEmpty()
      // 可在这里交给 TTS 播放
    },
    onError = { error ->
      // 展示或记录错误
    },
  )
}
```

调用前需要保证：

- 对应模型已经下载。
- 模型及 Agent session 已初始化。
- 当前没有另一轮推理正在执行。

通过正常的 `CustomTaskScreen` 进入页面时，`ModelManagerViewModel.initializeModel()` 会自动完成初始化。如果绕开现有导航创建独立 Activity/Screen，则需要显式初始化 `AgentRuntimeExecutor`，不应只拿到 `Model` 就直接推理。

## 5. 项目现有的语音输入能力

项目已经有两套容易混淆的音频能力。

### 5.1 SpeechRecognizer：语音转文字

文件：

```text
Android/src/app/src/main/java/com/google/ai/edge/gallery/ui/common/textandvoiceinput/HoldToDictateViewModel.kt
Android/src/app/src/main/java/com/google/ai/edge/gallery/ui/common/textandvoiceinput/HoldToDictate.kt
Android/src/app/src/main/java/com/google/ai/edge/gallery/ui/common/textandvoiceinput/TextAndVoiceInput.kt
```

`HoldToDictateViewModel` 使用 Android `SpeechRecognizer`：

- `startSpeechRecognition()`：开始识别。
- `onPartialResults()`：更新实时识别字幕。
- `onResults()`：得到最终文字并调用传入的 `onDone(text)`。
- `stopSpeechRecognition()`：停止本轮识别。

当前限制：

- 识别语言写死为 `en-US`，中文需要改成 `zh-CN` 或设备当前语言。
- `onError()` 是空实现，正式产品需要处理无语音、超时、网络和权限错误。
- Android 系统的 SpeechRecognizer 是否离线取决于设备所提供的识别服务和语言包。
- 当前组件是按住说话/一句话完成，不是真正持续的全双工语音流。

### 5.2 AudioRecorderPanel：录音直接交给多模态模型

文件：

```text
Android/src/app/src/main/java/com/google/ai/edge/gallery/ui/common/chat/AudioRecorderPanel.kt
```

它通过 `AudioRecord` 录制 PCM，再包装为 `ChatMessageAudioClip` 和 WAV 字节，最后通过：

```kotlin
generateResponse(audioMessages = ...)
```

送给支持音频的 Gemma 模型。该方式可以让模型理解一段完整录音，但仍然是“录完再发送”，不是边说边推理。

对于语音聊天第一版，优先建议 `SpeechRecognizer -> text -> generateResponse()`，响应速度和控制性通常更好；若希望模型直接理解语气、环境声或混合音频，再使用 `audioMessages` 路线。

## 6. 模型文字转语音

当前 Gemma 4 在本项目中只输出文字，项目也没有实现 `TextToSpeech`。要让 AI 开口说话，需要新增 Android TTS 层：

```text
模型 StreamToken/最终文本
  -> 句子切分与缓冲
  -> android.speech.tts.TextToSpeech
  -> 扬声器播放
```

第一版建议在 `onDone` 后朗读完整回答，实现简单稳定。后续若想降低等待时间，可在收到标点完整的句子后分段调用 TTS；不能把 UI 中不断累加的完整字符串反复送给 TTS，否则会重复朗读。

建议新增：

```text
SpeechToTextController.kt
TextToSpeechController.kt
VoiceConversationViewModel.kt
VoiceConversationScreen.kt
```

## 7. 推荐的语音对话状态机

```text
Idle
  -> Listening       用户讲话
  -> Recognizing     确认最终识别文本
  -> Thinking        模型生成
  -> Speaking        TTS 播放
  -> Listening/Idle  下一轮
```

状态约束：

- `Listening` 时不要播放 TTS，避免 AI 的声音被麦克风再次识别。
- `Thinking` 时通常不接受第二次提交，因为当前 session 只假定同时运行一个推理。
- 用户打断时同时调用 `TextToSpeech.stop()` 和 `viewModel.stopResponse(model)`。
- 页面退出时释放 SpeechRecognizer、TTS 和模型资源。
- 使用 Audio Focus，处理来电、音乐和其他音频应用的抢占。

## 8. 推荐的改造层级

### 第一阶段：一句一答

1. 复用 `HoldToDictateViewModel` 获取最终识别文字。
2. 把语言从固定 `en-US` 改为可配置或 `zh-CN`。
3. 复用 `addMessage()` + `generateResponse()`。
4. `onDone` 后读取最后一条 Agent 文本并用 TTS 播放。
5. UI 展示“正在听、正在思考、正在播放”状态。

### 第二阶段：更低延迟

1. 给 `generateResponse()` 增加可选的 `onToken(token)` 回调，或单独暴露响应事件 `SharedFlow`。
2. 将 token 累积到完整句子，再送入 TTS。
3. 支持用户点击/说话打断生成与播放。

### 第三阶段：连续语音体验

1. 增加静音检测/VAD 和自动结束一句话。
2. 增加回声抑制、音频焦点和耳机状态处理。
3. 设计自动重新开始监听的策略。
4. 处理屏幕锁定、后台运行和前台服务。

这仍然属于“轮流说话的低延迟语音对话”。当前 LiteRT-LM 接口接收的是完整文字或完整音频片段，不支持真正的麦克风流式输入；要实现电话式全双工对话，需要更换或扩展模型运行时。

## 9. 应调用哪些方法

| 目的 | 推荐调用 |
| --- | --- |
| 模型初始化 | 正常页面中使用 `ModelManagerViewModel.initializeModel()`；独立架构使用 `AgentRuntimeExecutor.initialize()` |
| 加入用户消息 | `LlmChatViewModelBase.addMessage()` |
| 发送识别后的文字 | `LlmChatViewModelBase.generateResponse()` |
| 接收页面级流式结果 | 观察 `viewModel.uiState` |
| 接收业务级 token | 收集 `AgentRuntimeExecutor.executeStream()` 的 `StreamToken` |
| 获取最终完整结果 | `LoopTerminated.finalResponse`，或 `onDone` 后读取最后一条 `ChatMessageText` |
| 停止生成 | `LlmChatViewModelBase.stopResponse(model)` |
| 最底层发送 | `LlmChatModelHelper.runInference()` / `conversation.sendMessageAsync()`，不建议 UI 直接调用 |
| 语音转文字 | `HoldToDictateViewModel.startSpeechRecognition()` |
| 文字转语音 | 当前没有，需要新增 Android `TextToSpeech` 封装 |
